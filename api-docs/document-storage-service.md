# Document Storage Service API Docs

Base path through gateway:

- `/api/v1/documents`

Responsibility: uploaded document metadata and object-storage gateway.

## Endpoints

### `POST /api/v1/documents/upload`

Summary: Upload a recruitment document such as CV, certificate, portfolio, or image.

Auth:

- Required
- Roles: authenticated internal user via gateway identity

Request:

- `multipart/form-data`

Request body:

| Field          | Type   | Required | Note                                                        |
| -------------- | ------ | -------- | ----------------------------------------------------------- |
| `file`         | file   | Yes      | Uploaded file                                               |
| `documentType` | string | Yes      | `CV`, `CERTIFICATE`, `PORTFOLIO`, `AVATAR`, `LOGO`, `OTHER` |
| `ownerType`    | string | Yes      | `candidate`, `company`, `application`                       |
| `ownerId`      | uuid   | Yes      | Owner id in the owning business service                     |

Allowed file types:

| Document type         | MIME types                                                                                                                                                  |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AVATAR` / `LOGO`     | `image/jpeg`, `image/png`, `image/webp`                                                                                                                     |
| `CV`                  | `application/pdf`, `application/msword`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `image/jpeg`, `image/png`, `image/webp` |
| `CERTIFICATE`         | `application/pdf`, `application/msword`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `image/jpeg`, `image/png`, `image/webp` |
| `PORTFOLIO` / `OTHER` | Same as document/image types above                                                                                                                          |

Max file size: `10MB`.

Example form-data:

```text
file=@cv.pdf
documentType=CV
ownerType=candidate
ownerId=b8b33c46-4bb0-4a33-8b0d-927e081a38a5
```

Success response:

```json
{
  "success": true,
  "data": {
    "id": "6b5f02d0-5aa1-4e5e-a5f6-9880cb3303db",
    "documentType": "CV",
    "ownerType": "candidate",
    "ownerId": "b8b33c46-4bb0-4a33-8b0d-927e081a38a5",
    "fileName": "cv.pdf",
    "mimeType": "application/pdf",
    "size": 123456,
    "key": "candidate/b8b33c46-4bb0-4a33-8b0d-927e081a38a5/cv/6b5f02d0-5aa1-4e5e-a5f6-9880cb3303db.pdf",
    "url": "https://minio.local/nexhire/..."
  }
}
```

Errors:

| Status | Code                             | Meaning                                           |
| ------ | -------------------------------- | ------------------------------------------------- |
| 400    | `DOCUMENT.FILE_REQUIRED`         | Missing `file` part                               |
| 400    | `DOCUMENT.FILE_TOO_LARGE`        | File exceeds 10MB                                 |
| 400    | `DOCUMENT.UNSUPPORTED_FILE_TYPE` | MIME type is not allowed for `documentType`       |
| 401    | unauthorized                     | Missing/invalid access token                      |
| 403    | forbidden                        | User cannot upload for this owner context         |
| 422    | validation error                 | Invalid `documentType`, `ownerType`, or `ownerId` |

FE notes:

- Use the returned `id` as `documentId` in candidate/application/profile flows.
- `url` is a temporary download URL generated by object storage.
- Do not infer ownership from `ownerId` on the client; backend services must validate ownership in their own business context.

## Internal endpoints

### `GET /api/v1/internal/documents/:id/download-url`

Internal only.

Summary: Create a short-lived download URL for an internal service such as application-service.

Auth:

- Required
- Internal service token header: `x-internal-service-token`

Success response:

```json
{
  "success": true,
  "data": {
    "id": "7bb46232-eb8d-40c8-ae0a-7e49ab98e26b",
    "documentType": "CV",
    "ownerType": "candidate",
    "ownerId": "d6dd534c-fd20-4cec-87c9-a6178e78f933",
    "fileName": "backend-cv.pdf",
    "mimeType": "application/pdf",
    "size": 234567,
    "url": "https://minio.local/nexhire/cv-url",
    "expiresInSeconds": 900
  }
}
```

Errors:

| Status | Meaning                                |
| ------ | -------------------------------------- |
| 401    | Missing/invalid internal service token |
| 403    | Internal caller is not allowed         |
| 404    | Document not found                     |

### `DELETE /api/v1/internal/documents/:id`

Internal only.

Summary: Remove a document object from MinIO and soft-delete its metadata row.

Auth:

- Required
- Internal service token header: `x-internal-service-token`

Success response:

```json
{
  "success": true,
  "data": {
    "deleted": true
  }
}
```

Notes:

- This is intended for asynchronous cleanup flows after the owning service has confirmed business retention.
- For candidate CV cleanup, candidate-service checks application-service retention first.
- If the document metadata is already soft-deleted, the endpoint returns `deleted: true`.

Errors:

| Status | Meaning                                |
| ------ | -------------------------------------- |
| 401    | Missing/invalid internal service token |
| 403    | Internal caller is not allowed         |
| 404    | Document not found                     |
